# Quick-Payment — ОСББ «Донця 2А-Ініціатива»

Сторінка швидкої оплати внесків та інших платежів ОСББ. Проєкт побудований на основі `SapozhnikUA/PE-QuikPaymentPage` і адаптований для кількох платіжних рахунків, QR-платежів НБУ та роботи з мобільними банківськими застосунками.

- **Робоча адреса:** https://dontsa2a.kyiv.ua/bank/
- **Репозиторій:** https://github.com/OSBB-D2A/Quick-Payment
- **Поточна версія:** див. файл [`VERSION`](VERSION)
- **Мова інтерфейсу:** українська

## Можливості

- Формування QR-коду платежу НБУ у форматі 002.
- Вибір платіжного рахунку ОСББ та відповідного призначення платежу.
- Кілька рахунків із незалежними списками призначень.
- Автоматичне формування призначення платежу з номером квартири або особового рахунку.
- Довідник квартир і нестандартних номерів у `apartments.json`.
- Введення суми платежу та її передавання в платіжному посиланні.
- Платіжне посилання з параметрами, придатне для копіювання та поширення.
- Відкриття сумісних банківських застосунків на мобільних пристроях.
- Відображення реквізитів отримувача та копіювання окремих полів.
- Експорт платіжних реквізитів.
- Світла й темна теми, адаптивне відображення для комп'ютерів і мобільних пристроїв.
- Захищений режим адміністратора для зміни конфігурації та встановлення оновлень.
- Параметр `block` у платіжних посиланнях для блокування зміни окремих полів.

## Платіжні посилання

Посилання може містити такі параметри URL:

| Параметр | Призначення |
| --- | --- |
| `a` | Ідентифікатор рахунку, якщо обраний не рахунок за замовчуванням. |
| `sum` | Сума платежу. Старий параметр `amount` також підтримується для сумісності. |
| `apt` | Номер квартири або особового рахунку. Значення `xxx` означає, що номер ще не вибрано. |
| `p` | Числовий ідентифікатор шаблону призначення. Для старих посилань підтримується попередній формат із Base64-текстом. |
| `purpose` | Текст призначення платежу; підтримується для сумісності зі старими посиланнями. |
| `desc` | Старий параметр тексту призначення, підтримується для сумісності. |
| `block` | Набір літер, що блокують зміну полів. Літери можна комбінувати в будь-якій послідовності. |

### Блокування полів через `block`

Літери параметра `block` не залежать від регістру; підтримуються такі значення:

- `p` — заблокувати зміну **рахунку** та **призначення платежу**.
- `s` — заблокувати зміну **суми**.
- `a` — заблокувати зміну **квартири / особового рахунку**.

Приклади:

- `?sum=500&block=s` — сума 500, поле суми заблоковане.
- `?a=dobrovilnii&p=2&block=p` — вибраний рахунок і призначення не можна змінити.
- `?sum=500&apt=123&block=sa` — сума та номер квартири заблоковані.
- `?sum=500&apt=123&block=psa` — заблоковано рахунок, призначення, суму та квартиру.

Невідомі літери в `block` ігноруються. Під час формування посилання підтримувані літери зберігаються в канонічному порядку `p`, `s`, `a`.

Якщо введено суму, але не вибрано квартиру для призначення, що потребує номера квартири / о/р, сума все одно зберігається в URL. Посилання може містити `apt=xxx`, щоб явно позначити незаповнений номер. Для завершення платежу потрібно вибрати квартиру.

## Структура проєкту

- `index.html` — інтерфейс, стилі, формування QR-коду, URL платежу та логіка клієнтської сторінки.
- `save.php` — серверний API, авторизація адміністратора, збереження конфігурації та механізм оновлення.
- `config.php` — робоча конфігурація на сервері; містить реквізити й хеш пароля адміністратора. Файл не зберігається в репозиторії та не перезаписується автоматичним оновленням.
- `config.example.php` — приклад структури конфігурації. Перший PHP-рядок-захист потрібно зберігати.
- `apartments.json` — довідник квартир / особових рахунків, якщо використовується.
- `VERSION` — номер версії, який показує сторінка та використовує механізм оновлення.
- `natural-green-bg.svg`, `profile-logo.svg` — фонове зображення та логотип сторінки.
- `og-image-square.svg` — зображення для Open Graph / попереднього перегляду посилань.
- `favicon.svg` — іконка сайту.

## Конфігурація

### Створення робочої конфігурації

1. Розмістіть проєкт на вебсервері з PHP.
2. Створіть робочий `config.php` на основі `config.example.php`.
3. **Не видаляйте перший рядок** `<?php http_response_code(404); exit; ?>` — він захищає конфігурацію від прямого перегляду через браузер.
4. Заповніть реквізити рахунків та інші налаштування. Не публікуйте робочий `config.php` у GitHub.
5. Переконайтеся, що вебсервер може записувати `config.php`, якщо адміністративний інтерфейс має зберігати зміни.

### Додавання платіжного рахунку

У масиві `accounts` у `config.php` додайте об'єкт із унікальним `id`. Основні поля:

- `id` — стабільний ідентифікатор рахунку, використовується в URL.
- `label` — назва, яку бачить платник у списку.
- `name` — повна назва отримувача.
- `iban` — IBAN отримувача.
- `tax_id` — податковий номер отримувача.
- `bank`, `mfo`, `bank_edrpou` — банківські реквізити.
- `default_purpose` — призначення за замовчуванням для рахунку.
- `purposes` — список доступних призначень; кожен елемент має `id`, `text` і `enabled`.

Приклад структури рахунку:

```json
{
  "id": "example",
  "label": "Назва рахунку",
  "name": "Повна назва отримувача",
  "iban": "UA000000000000000000000000000",
  "tax_id": "00000000",
  "bank": "Назва банку",
  "mfo": "000000",
  "bank_edrpou": "00000000",
  "default_purpose": "Призначення платежу",
  "purposes": [
    {
      "id": 1,
      "text": "Призначення платежу",
      "enabled": true
    }
  ]
}
```

Використовуйте справжні реквізити лише у власній серверній конфігурації. Ідентифікатори призначень мають бути коректними та стабільними. Призначення рахунку не повинні автоматично переноситися до іншого рахунку.

### Довідник квартир

За потреби зберігайте відповідності номерів у `apartments.json`. Формат файлу має відповідати тому, який уже використовується в актуальній конфігурації проєкту. Після редагування перевірте, що номери коректно з'являються у списку та передаються в платіжне посилання.

## Встановлення та оновлення

### Ручне розгортання

1. Завантажте репозиторій на вебсервер або розмістіть файли в каталозі сайту.
2. Налаштуйте робочу конфігурацію `config.php` окремо від Git.
3. Перевірте права доступу та відкриття сторінки через HTTPS.
4. Переконайтеся, що `index.html`, `save.php`, `VERSION` і графічні ресурси доступні за правильними шляхами.

### Оновлення через інтерфейс адміністратора

1. Увійдіть у режим адміністратора.
2. Натисніть **«Перевірити оновлення»**.
3. Перегляньте доступну версію та підтвердьте встановлення.
4. Після оновлення перезавантажте сторінку без кешу, якщо браузер показує старий інтерфейс.

Механізм оновлення завантажує дозволені файли з гілки `main`. Перелік файлів визначений у `UPDATE_CODE_FILES` у `save.php`. Коли додається новий ресурс, на який посилається інтерфейс, його необхідно додати до цього переліку, інакше на сервері може виникнути помилка 404.

**При кожній зміні коду, що публікується в репозиторії, збільшуйте номер у файлі `VERSION`.** Версія має відповідати зміні, яку отримує користувач під час оновлення.

Робочий `config.php` і секрети не повинні перезаписуватися механізмом оновлення.

## Вимоги до сервера

- PHP **7.4 або новіший**.
- HTTPS для безпечної роботи сторінки та сучасних функцій браузера.
- Дозвіл вебкористувачу читати файли проєкту.
- Дозвіл на запис до `config.php`, якщо конфігурація змінюється через адмінпанель.
- Працююча функція `mail()`, якщо використовується надсилання листа для анулювання ключа адміністратора.

## Адміністрування та безпека

- Для першого налаштування задайте пароль адміністратора через передбачений інтерфейс.
- Використовуйте довгий унікальний пароль.
- Не додавайте `config.php`, паролі, хеші, токени або резервні копії секретів до Git.
- Параметр `?admin` вмикає інтерфейс адміністратора в браузері; доступ до захищених операцій усе одно вимагає авторизації.
- Після зміни реквізитів перевірте назву отримувача, IBAN, податковий номер, банк, МФО та призначення перед публікацією посилань.

## Перевірка після змін

Після кожного релізу перевірте:

- сторінка завантажується без помилок у консолі браузера;
- фон, логотип і favicon не повертають 404;
- вибір рахунку оновлює відповідний список призначень;
- сума зберігається в URL навіть за незаповненої квартири;
- `apt=xxx` не сприймається як реальний номер квартири;
- параметри `block=p`, `block=s`, `block=a` і їх комбінації блокують відповідні поля;
- QR-код формується для валідного платежу;
- мобільні банківські посилання відкривають правильний застосунок;
- автоматичне оновлення встановлює номер версії з файлу `VERSION`.
